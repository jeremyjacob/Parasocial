- **Assemblies** — `assembly(name, ({ revolute, slider, cylindrical, planar, ball, fastened, fix }) => ...)` exported from a studio; joints attach at `part.at("name")` connectors (declared in a part body with `.connector(name, face | edge | { origin, axis })`, moved with transforms) or at literal frames. Parts are modeled in place: every joint is 0 at the modeled pose; limits are deg/mm from there. An assembly holds its own copies of the parts it names (instances, id `<assembly>/<part>`, e.g. `mechanism/lamp:turret`; `AssemblyInfo.instances`); the engine aliases an instance's geometry to its source part (`sourcePart()` in runtime/protocol), poses/interference/measure/export apply to instances only, and the source parts never move. The workspace shows one studio at a time (`ws.activeStudio`, remembered per document); the viewer holds only that studio's parts (meshes live in `WorkspaceState`), and the isolate toggle is gone. Solver: `packages/assembly` (own LM/Gauss–Newton, spanning tree + loop-closure residuals, DOF/movability via Jacobian rank, limits clamped). App: drag parts in the select tool (`assembly.svelte.ts`), poses saved in `documents.settings.poses[assembly][joint]` via `document.setPose` (undoable, no version), joint rows in the Parts tree. Interference: engine `interferences()` (OCCT common of posed shapes, bbox broadphase, cached, latest-wins) — only between assembly parts; red volumes in the viewer (I toggles). Measure/export use poses; pins, markup and note targets are stored in part coordinates. A studio exports parts or assemblies, never both (the engine reports a mix on the assembly). Copies: `insert(part, { name, place })` (id `<assembly>/<part>@<name>`, name required from the second copy on), connector-to-connector joints `revolute(a.at("x", i), b.at("y"), { flip })` that place the copy (0 where the connectors meet), connectors with several frames (`.connector("bolt", holes)` or an array; `part.at("bolt", i)`), and subassemblies `insert(otherAssembly, { name })` (flattened by the engine into scopes, ids `<assembly>/<sub>@<name>/<part>`, joints named `<sub>@<name>/<joint>`, the sub's `fix` becomes fastened joints so the whole moves; reach its parts with `sub.part(p)`). Home transforms come from `layout()` in packages/assembly (placed, else mated onto something laid out, else where modeled; scopes laid out inside-out); the solver takes a frame on each body (`T_b = T_a·F_a·M(q)·F_b⁻¹`) and per-body homes. `resolveAssembly()` (runtime/mechanism.ts) turns an `AssemblyInfo` plus regenerated connectors into a solver spec for the app and tests. Pattern counts can't come from geometry (the assembly body runs without it): share a constant. Example: examples/hinge. MCP: `set_pose` / `set_param` default to scope "session" (preview held in memory on the MCP session, `packages/mcp/src/preview.ts`: no version, no configuration, nothing others see; scope "shared" saves via `document.setPose` / the active configuration); render/describe_model/measure/check/export solve poses like the app (shared values, then the session's) and accept instance and assembly ids; render takes `up: "z" | "y"` (default z, the viewer's). Not yet: closed-loop examples; joint couplings (gears).
- **Live notes (Claude Code channel)** — `packages/mcp-local`: a stdio bridge (`parasocial-mcp --url <…/mcp> [--channel]`, plus `login`/`logout`) that proxies tools/resources to one remote /mcp session (OAuth loopback client, tokens in `~/.parasocial/auth.json`, refresh rotation serialized across processes by a lock; reconnects on a 404 session).
